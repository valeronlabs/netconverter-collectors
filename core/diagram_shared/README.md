# NetConverter Precision Outline 1.0.0

The approved A masters are product assets: 24 `nc-*` SVG identifiers, a 48-unit
viewBox, restrained blue `#2563eb`, charcoal `#24282f`, and monochrome counterparts.
Use at 24, 32, 40 or 48 px; preserve the viewBox and stroke geometry. The catalog
is `icons.json`. Connection anchors are positions on the drawing, not ports.

## Contract

`build_diagram(snapshot, kind=..., provenance=...)` produces `nc.diagram.v1`, a
derived presentation document. It does not parse vendor configurations, discover
devices, change NCIR, evaluate policy, or set a correctness verdict. The host must
authorize tenant/owner and selected device scope, select the immutable validated
source or existing emitted-target readback, and project its privacy view first.
Never supply a mapper's target IR as proof of emitted configuration.

The document contains schema/library/icon versions; a content-derived ID; kind
and side; source/job/revision/scope/view provenance; nodes; edges; groups; coverage;
and the user-editing notice. Nodes and edges carry scoped evidence locators and
one of `configured`, `observed`, `modeled`, `inferred`, `unknown`. Current builders
emit only explicit configured relationships and supplied evaluator/probe records.
The graph never invents external neighbors, a successful packet or equivalence.

Inputs may use existing flat IR or NCIR `core` / `modules.routing` /
`modules.policy` / `modules.vpn` shapes. Native selected-device adapters may
provide the same presentation fields plus their original `evidence_refs` and
static `diagram_limitations`. JSON pointers retain the original serialization
location. Comparison references carry a `source:` or `target:` prefix. Native
evidence references use their adapter's documented locators. Identical interface
names resolve only inside the same VRF/VSYS/VDOM/device-group/domain/layer/install
namespace; missing or ambiguous bindings produce coverage notes.

Five kinds are supported: topology, comparison, NAT, policy and traffic. Traffic
requires a recorded or existing-evaluator result; no result produces an explicit
unavailable scene. Empty target evidence produces an unavailable comparison.
Comparisons show structural changes, not semantic equivalence. Row position is
part of identity for ordered lists; reordering can therefore appear as changes.
No findings or optimization recommendations are generated by this library.

## Rendering and embedding

`render(document, format)` emits SVG, PDF, PNG, draw.io or JSON. One deterministic
two-column scene supplies every graphical renderer. Large diagrams split into
bounded pages; connectors crossing pages have explicit continuation notices.
The graph JSON and editable draw.io retain every selected endpoint and label.
Bounds disclose omitted records. Source evidence and original tables remain
authoritative. Long captions abbreviate visibly; original text is retained.

SVG embeds the bundled licensed Vera font. PDF uses that same font; PNG and FPDF
outline its glyphs before rasterization, so operating-system fonts are irrelevant.
Characters outside the bundled font use visible Unicode escapes and a coverage
notice; JSON, SVG titles and draw.io retain the original Unicode label. PNG is a
bounded composite overview; PDF and `png_pages()` retain full-size scoped pages.
Draw.io has native movable icon vertices, editable labels and real edge cells.
It has no external assets or flattened-background dependency.

Use `reportlab_flowables`, `append_fpdf`, `html_overview` and `png_pages` with
existing report engines. `diagram_bundle` returns paths/bytes plus
`diagrams/manifest.json` containing SHA-256, media type, size, diagram identity and
provenance. Rendering failures are explicit manifest errors, never job verdicts.
Do not change diagrams after IDs are computed. Regeneration creates new artifacts;
it never replaces historical evidence. Engineer edits remain user documentation.

## Distribution

`scripts/export_diagram_shared.py NEW_DIRECTORY` exports only files enumerated
in `runtime.json`, plus `diagram-shared.lock.json`. It refuses uncommitted source
unless `--allow-dirty` is supplied for development. Never release a development
pin. The lock binds every byte to the engine commit; consumer release checks must verify
it before packaging. Appliance destination is `engine/app/diagram_shared`; collector
destination is `core/diagram_shared`. Paths inside the lock retain engine names.
No API, conversion pipeline, KB, mapper or server authentication code is exported.

Runtime dependencies are pinned in the host requirements. Cairo is local/offline
(`libcairo2` on Debian). The pure graph builder and SVG/draw.io/JSON serialization
have no network calls. Authorization, privacy projection, download revocation and
client-facing capabilities belong to the host, not this distributable package.
